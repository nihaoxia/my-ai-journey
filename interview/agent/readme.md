# Agent 智能体？
字面意义上，AI会自己干活
这么理解没问题，但遮住了一个更重要的问题。

Agent 和 普通的AI对话 差别在哪里？
结构导致的 Agent 工作方式
- 对话结构
  普通对话，你问它答，一问一答就结束
  案例： 帮我写一封邮件
  llm 写完了 任务就终止
  就是问答机器 输出一次，没有后续
  Agent不一样 它有一个持续运转的结构
  你给它一个任务 它会去拆任务，决定下一步 去调用工具 看结果。
  这过程是一个循环 ， 直到任务完成或者它自己判断(超出循环次数、
  token上限、相同结果次数，失败了)

## Agent 工作方式，核心三个动作
- 第一个动作 思考 Reasoning 
- 第二个动作 行动 Act
- 第三个动作 观察 Observe

一轮的 观察后再回到思考、再行动、再观察 循环往复
这个循环就叫 ReAct
ReAct = (Reasoning + Act + Observe) 是一套标准的Agent执行流程/Agent 工作框架 不是langchain 那种大型开发库，是Agent通用的循环工作标准

## demo
帮我写分析的竟品，然后去写一份报告。   Agent会怎么做。

- 第一轮它会先去思考(Reasoning)
  需要去搜索竞品的信息
  调用搜索工具(act)，去咨询三家竟品的最新动态
  查完以后 , 把结果拿回来。
  然后观察(Observe) 信息量挺大。
  到这里第一轮结束了，接着第二轮。

  再回到思考，发现缺少财务数据(reason)
  可以去官网或查股市api(Act)
  去抓取相应的数据
  观察
  第三轮、第四轮...
  最后一轮，把报告写完，交给我们。

  Agent 最核心的动作，就是 Tool Use
  工具 是Agent的手和脚，没用工具它只能在脑子里转
  转完之后只有文字
  常见的工具：
  - 搜索工具 能上网查实时信息
  - 代码执行器，能运行代码 能看结果。
    Anthicic 最牛的 Agent企业 ，代码是最标准，有完善的工程化验收机制的，ai测试agent
    文无第一，武无第二(claude)
  - 文件读写I/O
  - 浏览器的操控browser 打开网页 点击提交

  - API 调用
