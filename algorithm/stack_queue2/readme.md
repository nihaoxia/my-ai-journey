## 链表
- 数组扩容，arr.length >= capacity 扩容和初始化的时候有内存申请的开销，其余时刻是没有的
- 链表 每次都申请 平均的
数据规模 
小就用数组
大就用用链表
数组的优势  遍历，索引取元素，缺点是增删，移动位置和申请空间
链表的优势 增删（前驱节点，不要坐过站）缺点是找到相应的节点

链表和数组是相似的，他们都是**有序**的列表（list）,都是线性结构（有且只有一个前驱和后继）
array 索引
linked list head -> node ... -> tail


链表中，数据单位节点，指针
节点和节点的分布是不连续的，是离散的
// js 对象字面量
{
  val:2,
  next:

}

head 节点？
访问链表中的任何一个元素，从起始节点开始(val 空)，逐个访问next，一直访问到目标节点为止，tail节点(next空)

## 删除
前驱节点

假设数组的长度是n,因增加或删除操作需要移动的元素数量，会随数组长度n的增大而增大，呈现一个线性关系。
增加删除操作对应的复杂度是O(n)
- js数组特性

js数组未必是真正的数组
如果每一项类型一致，存数组，连续内存
如果类型不同，一段非连续内存，js数组不再具有数组的特征，底层使用哈希分配内存空间

链表高效的增删操作
O(n) 固定的
明确要插入/删除的目标位置，接着只需要改变目标节点及其前驱/后继节点的指向(O(1))
麻烦的访问操作O(n)
